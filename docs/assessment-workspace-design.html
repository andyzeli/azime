Freeze complete input and reference definitions. Read source versions together in a consistent transaction.

Prep is optional, but its useful context is not silently lost. If included, retain its original scope and version. Old trajectories and priorities are pre-exam context; current diagnoses and visit evidence govern the new analysis. If absent, pass the case summary/timeline directly.

Proposed changes require the post-exam prompt and schema to change together. The current schema requires refinedAnalysis, and the current builder copies scope and fullReviewedAnalysis from Exam prep.

  ]

// Generate after reviewing B's treatment analysis.

prep.assessmentRevision === 8; // still valid as the sheet used that day
No return to preparation. The physician changes the current assessment, completes any missing evidence, and generates a new post-exam snapshot.

Readiness belongs to actions

ActionRequirement
Save / navigate / enter findingsValid data and revision check. No diagnosis confirmation or prep prerequisite.
Generate prepUsable 3A baseline for selected working diagnoses. Save the current assessment first; unreviewed AI judgments stay explicitly unreviewed.
Generate draft post-exam analysisCoherent saved assessment + visit input; missing treatment coverage and unresolved judgments remain visible. No requirement for a current prep artifact.
Finalize conclusions / reportPhysician explicitly resolves or documents uncertainty in relevant diagnosis and treatment judgments. Required note, questionnaire and referral-answer rules remain separate product rules.
Finalize a ratingApplicable physician MMI decision, supported diagnosis and completed rating prerequisites. Draft findings never imply rating eligibility.

An empty current diagnosis set can still support a report explaining non-support. It must not silently produce “no treatment issues” or “0% impairment.”

07Smallest coherent implementation

  1. Give current scope a durable owner. Extend regional steering storage with diagnosis state. Move Visit diagnosis decisions there; retain legacy data during migration.
  2. Extract reusable Analysis editors. Preserve treatment controls and resolver. Remove numbered progression and the rejected-diagnosis redirect/blocker.
  3. Unlock findings independently. Candidate lookup uses current working scope. Allow assessment answers before diagnosis support/history eligibility; retain unlinked findings in post-exam evidence.
  4. Separate snapshot builders. Prep retains the reduced projection. Post-exam resolves current steering directly and uses the full projection. Prep becomes optional context.
  5. Handle scope changes without destructive resets. Filter removals; merge additions by explicit identity. Full 3A regeneration is a separate operation requiring review of affected carried-over judgments.
  6. Freeze output versions. Preserve generated prep; bind priority responses to the specific prep artifact + priority identity. Mark downstream results “inputs changed” after relevant edits.

Assessment changes while an AI addition is running.Reject stale write; reload/reconcile. Never overwrite newer steering.

Recommendation: keep the useful Analysis tab, make its state authoritative, and let preparation and post-exam analysis branch from it. Snapshot the inputs at generation time; do not make a printed preparation artifact control the live assessment.
