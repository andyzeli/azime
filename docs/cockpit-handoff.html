Current direction

There's no stepper. Each part of the cockpit is an input:

  • Analysis holds the shared assessment: the diagnosis list and the treatment review.
  • Prep sheet is an optional printout in a modal. It isn't a workflow step.
  • Visit is where evidence is entered, during the exam or afterward.

Diagnosis list

One list per case and region, in table case_region_diagnoses (migration 0014), read and saved through GET/PUT /cases/:id/diagnoses/:region. It's kept separate from steering, because steering belongs to a single 3A run.

{ canonicalDx, source: "records" | "added",
  status: "working" | "supported" | "not_supported", reason }
  • Every listed diagnosis needs a verdict. A wrong diagnosis is marked Not supported with a reason. Only diagnoses the physician added can be removed.
  • Before the first save (revision 0), the list is the 3A scope plus every records diagnosis, all set to Working.
  • Editor: components/DiagnosisList.tsx, in the Analysis setup strip. Every change saves immediately.

Prep sheet

  • Where it lives: components/ExamPrepModal.tsx. It's opened by ?prep=true in the URL, which useExamPrepModal() sets.
  • How to open it: the "Prep sheet" button at the right of the case header, or the Visit priorities header. The header button is disabled until some region has exam prep, and it shows "out of date" when the sheet is stale.
  • Toolbar:
    • the AMA mode control, which also appears in the Analysis header;
    • Update sheet, which only updates regions whose steering has been saved;
    • Print, which prints exactly what's shown, with a footer that says how current each part is.
    Opening the sheet never runs AI.
  • Analysis footer: "Save steering" is the primary button. "Update prep sheet" is secondary; it saves steering if needed and then runs 3B.
  • "Out of date" compares contents, not revision numbers. A saved edit that is later undone doesn't count. It checks:
    • the exam prep scope against the current diagnoses;
    • the steering each run used against the saved steering;
    • whether 3A has been re-run.

input = { caseContext, region, caseSummary,

output += trajectoryAnalysis           // moved from exam prep
basedOn = { caseSummaryId, 3A id/updatedAt, steering rev, diagnoses rev,
            visit rev, pdq id/updatedAt, questionnaire ids }
  • A current diagnosis with no 3A coverage is allowed, but flagged as "no treatment analysis" rather than "no issues".
  • AMA findings are kept even when no linked diagnosis remains, or the diagnosis is not supported.
  • Assessment footer (not Visit) gets the readiness checklist and "Run post-exam analysis": visit documented, every diagnosis decided, every row reviewed, every current diagnosis analyzed. The Visit footer just drops "needs exam prep".
  • Remaining care isn't a pass 4 output. It's computed from steering after the visit (applicable and not adequately trialed, for current diagnoses), and the physician confirms it in Opinions. Design pass 4's output around what Opinions shows.

Phase 3 plan (add a diagnosis without resetting steering)

Adding a diagnosis runs 3A for that diagnosis only. The model gets the existing rows as input, so it assesses them and doesn't suggest them again.

type PreExamDelta = {
  canonicalDx: string;                       // the added diagnosis
  existingRowAssessments: { rowId: string; assessment: TreatmentAssessment }[];
  newRows: TreatmentRow[];                   // source: "taxonomy" | "ai" only
};
Delta itemMerge
Existing rowAppend the assessment for the new diagnosis (unreviewed). Row id, prior assessments, and steering are untouched.
New taxonomy rowAdd if its treatmentId isn't present. If its episodeIds overlap a record_only row, upgrade that row instead (keep its id, set treatmentId, add the assessment), so there's no duplicate.
New ai rowAdd as a suggestion, assessed for the new diagnosis only, unreviewed. No server-side fuzzy dedupe; the prompt says not to repeat existing rows.
record_onlyNever created by a delta. Records don't change when a diagnosis is added, and the original 3A already made every non-taxonomy episode a record_only row. The only possible change is an episode gaining a taxonomy home, which is the upgrade case.

Removing a diagnosis is a filter, which already works through status. A full 3A regeneration stays a separate, explicit action.

Visit document

One JSON document per case, read and saved through GET/PUT /cases/:id/visit with expectedRevision.

{ note, pdqId, includedQuestionnaireIds, priorityResponses,
  amaHistory:     [{ region, canonicalDx, confirmed }],
  amaAssessments: [{ id, region, canonicalDxIds, rowId, nerveRoot, side,
                     answers, motorGrades, atrophyCm }] }
  • One assessment = one AMA row + the actual root + side. A bilateral finding is two assessments.
  • Diagnoses that share a component share one assessment (canonicalDxIds).
  • A missing or null answer means unresolved, never false.
  • Strength: a grade per muscle (motorGrades) derives the motor_* answers.
  • Atrophy: centimetres per measurement site (atrophyCm) derive the atrophy bands. Circumference tasks are split by site (thigh/calf, upper arm/forearm).
  • Reflex is the only check-all-that-apply section left.
  • Save validation rejects:
    • a bad root or side;
    • an unknown question or task;
    • derived answers that don't match the grades or measurements.

Post-exam snapshot

"Save & run post-exam analysis" adds a row to case_post_exam_analysis: a frozen copy of everything pass 4 will read. AI generation is still disabled (it returns 501).

  • visit.amaFindings stores each answer next to the test and question text that produced it, so the report can say what was tested.
  • It's currently built from exam prep. Phase 2 changes that (see above).

AMA

  • Reference data is maintained by the user:
    • ama_diagnostic_rows;
    • canonical_diagnoses.ama_row_ids / ama_rating_table_ids;
    • ama_rating_tables. Only the myelopathy diagnoses map to tables in v1.
    Import with pnpm --filter backend ama:import.
  • Mode is set per case (patientcase.ama_mode):
    • rating: everything;
    • guidance: rows and findings, but no rating tables;
    • off: hidden. The default is rating for work-injury cases and off otherwise.
  • Class/modifier picker (AmaClassScaleSelector): its choices are local only and not saved yet.
  • Exam prep root and table pre-selection isn't saved either, by design for now.

Roadmap after the redesign

  1. Save rating-table answers (class and modifier per table).
  2. Imaging review card: per study, agree or disagree with the radiologist and record the physician's own findings.
  3. Function and work capacity card, structured. Decide the data model first.
  4. Deterministic AMA evaluator, plus imaging and function data in the post-exam snapshot.
  5. MMI & Report tab: opinions, answers to the standard questions, and any custom questions, drafted by AI and edited by the physician.

Not planned: a SOAP-structured note, or merging priorities into the AMA findings.

Per-case referral questions were removed on 2026-10-17, because the standard question set covers them. Questions outside that set become custom questions in MMI & Report. Still waiting on a decision: the patient_declined prompt line.
