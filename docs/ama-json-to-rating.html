IME · Implementation walkthrough

AMA JSON → visit questions → WPI

The JSON supplies the checklist, question definitions, matching rules, and impairment values. The app queries it, saves physician answers, and evaluates the rules.

Real example: cervical C3 row 17-19-05 · Proposed application wiring; code below is pseudocode.
01

Query the preparation checklist

After canonical diagnoses are confirmed for Analysis, fetch their mapped rows. No root filter yet when roots are unknown.

For example, cervical_radiculopathy returns the mapped cervical root rows. Their examination_tasks describe what to examine.

Show each task ID once. Preserve every source row and its question IDs when combining identical tasks.

Assumes import converts region names to the app format, e.g. cervical_spine.
SQL · confirmed diagnoses → full candidate rows 
SELECT DISTINCT r.*
FROM canonical_diagnoses d
JOIN ama_diagnostic_rows r
  ON r.row_id = ANY(d.ama_row_ids)
WHERE d.id = ANY(:confirmedDxIds)
  AND d.region_id = :region
  AND r.region_id = :region;
Group tasks; keep their links 
checklist = new Map()
for (row of rows) {
  for (task of row.examination_tasks) {
    item = checklist.get(task.id) ?? {
      ...task, sources: []
    }
    item.sources.push({
      rowId: row.row_id,
      questionIds: task.question_ids
    })
    checklist.set(task.id, item)
  }
}
02

Use task links to open the right questions

In Visit, the physician confirms C3, left and selects the C3 row. Filter candidate root rows by nerve_roots; retain non-root candidates for their own confirmation.

Each task’s question_ids locates questions inside its source row. The question provides the control type, options, and help.

A task can link to several questions. Completing a task does not automatically make their criteria true.

Diagnosis and history confirmation are prerequisites. The row’s CS and any diagnosis-history questions still appear even though examination tasks only link to PE.

03

Initialize answers, then save the visit

Create an assessment when a row/root/side is selected. Initialize every row question to null, including CS. Reopen an existing assessment without resetting its answers.

In this example the physician chooses diminished pinprick with sharp/dull intact, then confirms a qualifying study/operative alternative.

Save amaAssessments in the existing case_visit_documentation.documentation JSONB. No separate answer table is needed.

null = unanswered. false = answered No. Save question values, not task completion flags or an entered percentage.

04

Evaluate the row’s entries, highest first

The root helped select the row. Answers now select an entry within that row.

Read entries[].criteria directly. For example, C3 entry 1B requires both:

cs_confirmed === true
AND
sensory_status === "diminished_pinprick"

All diagnosis/history/scope prerequisites must be confirmed before selection. The backend computes the result from saved answers.

Shared evaluator · no per-row if/else code 
for (entry of sortByClassThenGradeDescending(row.entries)) {
  state = evaluate(entry.criteria, assessment.answers)
  if (state === "unresolved") return { status: "incomplete" }
  if (state === "met") return {
    rowId: row.row_id,
    entryId: entry.entry_id,
    impairment: entry.impairment
  }
}
return { status: "no_supported_entry" }

Rule semantics: a missing leaf answer is unresolved. all fails on any false; any succeeds on any true. Otherwise unknown children keep the result unresolved. at_least succeeds at the required count, fails if true + unknown cannot reach it, and is otherwise unresolved.

An unresolved higher entry blocks a definitive lower choice. “No supported entry” does not mean 0% WPI.
